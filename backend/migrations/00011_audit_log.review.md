# 00011 审计哈希链：评审与回滚说明

## 差异与影响

- 新增 `audit.log`，保存操作时间、操作人、角色、操作、对象、详情、IP、请求 ID、前序哈希与 SHA-256 哈希。
- 新增仅供触发器使用的 `audit.chain_state`。事务级咨询锁与该单行锁把并发追加串行化；插入触发器覆盖调用方给出的时间与哈希，链头仅由数据库计算。
- 新增 `pgcrypto` 扩展（已获董事会批准）以计算 SHA-256。
- `audit_writer` 仅有 `audit.log` 的 `SELECT`/`INSERT` 和序列权限；`UPDATE`/`DELETE` 无权限。即使高权限应用角色获得更新权限，触发器也以 SQLSTATE `55000` 拒绝改删。
- 不涉及 `ledger` 表或余额；不跨 schema 读取或写入。

## 双人评审要点

1. 审查哈希负载的规范化：UTC 微秒时间、原始前序哈希、操作人、操作、对象及 canonical `jsonb` 文本，字段以 ASCII Unit Separator 分隔。
2. 审查 `audit.chain_state` 的锁次序与 `SECURITY DEFINER` 函数的固定 `search_path`，确认调用方无法伪造哈希或直接修改链状态。
3. 审查角色授权：`audit_writer` 对日志只可读/追加；报表角色不能读取链状态；所有角色的日志更新/删除均被拒绝。
4. 审查异地锚定适配器的目标、保留期、凭据注入及成功确认；这些外部参数尚未由董事会指定，因此本迁移不伪造投递实现。

## 回滚方案

- 开发或尚未写入审计记录的环境：可执行 goose `down`，删除本迁移的表、函数和 `pgcrypto`。
- 已写入记录的生产环境：**禁止执行 down**，否则会破坏只追加证据。紧急止损应先停止审计写入的应用路径、撤销 `audit_writer` 的登录成员资格并保留数据库/WAL 备份；后续只允许通过新的前向迁移修复。
- 上线前先在隔离 PostgreSQL 做 `up → 验证 → down → up`；上线后确认角色权限、链连续性和异地每日锚定成功记录。
