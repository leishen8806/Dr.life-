# KESS `REVIEW` 付款人工处理手册

`REVIEW` 表示平台已创建过付款意向，但 KESS `queryorder` 返回查无此单或结果仍无法被服务端确认。它不是付款成功，也不是付款失败。系统会降低频率继续查单，且不会自动关闭该意向。

## 客服处理

1. 记录父订单号、平台支付号 `trade_no`、进入 `REVIEW` 的时间和买家反馈；不要索取密码、银行卡资料或让买家重复付款。
2. 告知买家“付款正在核对”，在财务确认前不要取消、重新付款或承诺到账。
3. 若买家提供付款截图，只能作为人工核对线索，不得据此把订单改为已付款。

## 财务核对

1. 只使用 KESS 商户后台或受控的服务端 `queryorder`，按原 `trade_no` 查询；不得新建支付号替代原记录。
2. 同时核对商户号、订单号、币种和金额。任一不一致，保留 `REVIEW`，登记异常并升级给安全与账务审查。
3. KESS 明确返回 `SUCCESS` 时，等待后台任务按同一支付号入账。不得直接改数据库状态。
4. 若订单已取消、预留已释放或意向为 `INVALIDATED`，到账结果会进入 `payment_reconciliation_task`。财务按退款流程处理，订单不得恢复为已付款。
5. KESS 明确返回 `CLOSED` 或 `FAILED` 时，保留查询凭据并交由授权人员通过后续人工处置入口处理；当前版本不提供直接改状态的后台入口。

## 完成与升级

- 只有系统主动查单确认 `SUCCESS` 并完成幂等入账，或授权人员依据 KESS 的明确终态完成后续处置，才可关闭工单。
- 连续查询仍无结果、金额/币种/商户号不一致、出现多个 KESS 流水号，或退款无法完成时，升级给财务负责人和 SecurityReviewer。
- 所有查询时间、结果、操作人和退款凭据必须进入审计记录；聊天截图不能替代 KESS 查询结果。
